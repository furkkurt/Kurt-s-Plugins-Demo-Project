RPG Maker MZ eklenti temelleri

Oyun nasıl çalışır (çok kısa)

MZ bir JavaScript oyunudur. Çekirdek sınıflar js/rmmz_*.js içindedir (ör. Game_Player, Sprite_Character, Scene_Map). Her karede SceneManager aktif sahneyi günceller; sahneler pencereleri ve spriteları günceller.

Eklenti dosyası nedir?

Tek bir .js dosyasıdır. Üstte /*: ... */ bloğu plugin komutları için meta veridir: @plugindesc, @param vb. Editör bu metni okuyup Plugin Manager’da form oluşturur.

PluginManager.parameters('EklentiAdı')

Plugin Manager’daki değerler string sözlük olarak gelir. Sayı/boolean için Number(...), === 'true' gibi dönüşüm sizde.

Neden (() => { 'use strict'; ... })();?

IIFE (anında çalışan fonksiyon): global alanı kirletmemek için. Eklenti yüklendiğinde bir kez çalışır; içindeki const’lar dışarı çıkmaz (MZ global’larına yine window.X veya prototype ile erişirsiniz).

Prototype “alias” kalıbı (en önemli desen)

Mevcut fonksiyonu değiştirmeden sarmalamak için önce referans saklanır, sonra aynı isimle yeni fonksiyon atanır:

const _Eski = SomeClass.prototype.foo;
SomeClass.prototype.foo = function(...args) {
  // önce / sonra ek mantık
  return _Eski.call(this, ...args);
};

Böylece çekirdek güncellense bile zincir korunur. TypeScript’te de aynı mantık: önce const _orig = ..., sonra atama.

Oyun verisi vs. ekran (mantıksal / görsel)

  • Mantık: Game_CharacterBase, Game_Player, Game_Map — “oyunda ne oluyor”.
  • Görsel: Sprite_Character, Spriteset_Map — “ekranda nasıl çiziliyor”.

Animasyon kare indeksi gibi şeyler genelde mantık tarafında (_pattern); kırpma dikdörtgeni çoğu zaman sprite tarafında.

Eklenti sırası (plugins.js)

Üstteki eklenti önce yüklenir. Bir eklenti diğerinin patch’ini tekrar sararsa sıra önemlidir. Örneğin harita ön planı zoom/lag ile uyum için belirtilen sıraya uymak gerekir.

js/plugins.js ve $plugins

Editör bu dosyayı üretir; her öğe name, status, parameters içerir. Oyun başlarken çekirdek eklenti listesini okur; sizin kodunuz PluginManager.parameters('TamDosyaAdı') ile aynı name anahtarını kullanmalıdır (dosya adı .js olmadan).

Sahne (Scene) ve pencere (Window)

  • Scene_*: Tam ekran durum makinesi (başlık, harita, savaş, menü). create() içinde pencereler oluşturulur.
  • Window_*: Dikdörtgen içinde metin/seçenek çizer; update ile giriş alır.
  • Sprite_*: Oyun dünyası veya UI görseli; PIXI tabanlı.

Menü ekranı — AltMenuScreen ve düzenleme

Dosya js/plugins/AltMenuScreen.js · Yazar Yoji Ojima (MZ ile gelen örnek eklenti) · Parametre yok

Bu bölüm, RPG Maker MZ’ye hiç bakan biri için menünün nerede tanımlandığını ve AltMenuScreen’in varsayılan düzeni nasıl değiştirdiğini özetler. Projede menü görünümü için ayrıca KurtsOptionsMenu.js (arka plan, font vb.) kullanılıyor; AltMenuScreen ise yalnızca pencere yerleşimi ve çizim ile ilgilidir.

Menü “ekranı” nedir?

Haritada menü tuşuna basınca oyun Scene_Menu sahnesine geçer. Sahne, birkaç pencere oluşturur:

  • Komut penceresi (Window_MenuCommand): Eşya, Beceri, Donanım, Kaydet…
  • Altın penceresi (Window_Gold): Parti parası.
  • Durum penceresi (Window_MenuStatus): Grup üyelerinin yüzü, adı, can/MP çubukları.

Pencere boyutu ve ekrandaki yeri, sahnedeki *WindowRect() metotlarıyla hesaplanır; pencere içinde ne çizileceği ise Window_* sınıfındaki drawItem, maxCols gibi metotlarla belirlenir.

Varsayılan düzen (eklenti kapalı)

Çekirdek kod (js/rmmz_scenes.js) menüyü yan yana iki sütun gibi düşünür:

┌──────────────┬────────────────────────────────┐
│  Komutlar    │                                │
│  (~240 px)   │   Grup durumu (dikey liste)    │
│              │   4 satır, yüz solda metin sağda│
│              │                                │
│  [Altın]     │                                │
└──────────────┴────────────────────────────────┘

mainCommandWidth() sol şerit genişliğini 240 piksel yapar. Komutlar tek sütunda uzun bir liste; durum penceresi kalan genişliği kaplar.

AltMenuScreen ne değiştirir?

Eklenti, “komutlar solda / durum sağda” yerine üstte komutlar, altta durum düzenine geçer; her iki pencere de ekran genişliğini (Graphics.boxWidth) kullanır.

┌──────────────────────────────────────────────┐
│  Komutlar (4 sütun × 2 satır = 8 hücre)      │
├──────────────────────────────────────────────┤
│  Grup durumu (4 sütun × 1 satır = 4 kart)    │
│  [kart][kart][kart][kart]                    │
├──────────────────────────────────────────────┤
│  Altın (tam genişlik, en altta)              │
└──────────────────────────────────────────────┘

Özet: daha “konsol RPG” tarzı yatay komut şeridi ve parti üyeleri tek sırada.

Eklenti nasıl “bağlanır”? (prototype değiştirme)

Dosya bir IIFE içinde çalışır; yüklendiğinde mevcut sınıfların prototype üzerindeki fonksiyonları doğrudan yeniden atar (alias saklamaz — bu eklenti için yeterli, çünkü orijinal gövdeyi çağırmıyor).

MZ’de sınıf adları global’dır: Scene_Menu.prototype.commandWindowRect = function() { ... } yazdığınız anda, bir sonraki menü açılışında motor sizin fonksiyonunuzu kullanır.

Adım adım: hangi fonksiyon ne işe yarar?

1) Scene_MenuBase — yükseklik yardımcıları

Scene_MenuBase.prototype.commandWindowHeight = function() {
    return this.calcWindowHeight(2, true);  // 2 satır, seçilebilir pencere
};
Scene_MenuBase.prototype.goldWindowHeight = function() {
    return this.calcWindowHeight(1, true);  // altın şeridi 1 satır
};

calcWindowHeight(satırSayısı, seçilebilirMi) çerçeve + padding dahil piksel yüksekliği verir. AltMenuScreen bu iki değeri Scene_Menu içinde üst üste dizmek için kullanır.

2) Scene_Menu — pencere dikdörtgenleri (Rectangle)

Her *WindowRect() dört sayı döner: x, y, genişlik, yükseklik.

  • commandWindowRect: Üst şerit — wx=0, wy=mainAreaTop(), tam genişlik, yükseklik = komut penceresi yüksekliği.
  • statusWindowRect: Orta bölge — komut + altın yüksekliği çıkarılarak kalan mainAreaHeight() kullanılır; wy komutların hemen altı.

mainAreaTop() / mainAreaBottom() / mainAreaHeight(): Dokunmatik UI’deki iptal/sayfa düğmeleri ve (varsa) yardım penceresi dışında kalan “asıl içerik” alanı (Scene_MenuBase).

3) Scene_ItemBase — eşya/beceri hedef seçimi

Scene_ItemBase.prototype.actorWindowRect = function() {
    const rect = Scene_Menu.prototype.statusWindowRect();
    rect.y = this.mainAreaBottom() - rect.height;
    return rect;
};

Eşya veya beceri kullanırken “hangi aktör?” sorusu için Window_MenuActor açılır. Varsayılan bu pencereyi sol geniş şeritte tutar; AltMenuScreen aynı boyutu alıp ekranın altına yapıştırır — menüdeki parti kartlarıyla görsel tutarlılık için.

4) Window_MenuCommand — komut ızgarası

Window_MenuCommand.prototype.maxCols = function() { return 4; };
Window_MenuCommand.prototype.numVisibleRows = function() { return 2; };

Window_Selectable (ata sınıf) listedeki her öğenin hücresini maxCols ve numVisibleRows ile böler. 4×2 = en fazla 8 komut hücresi görünür (Eşya, Beceri, Donanım, Durum, Düzen, Seçenekler, Kaydet, Oyundan çık gibi).

5) Window_MenuStatus — parti kartları ve çizim

Yine 4 sütun, 1 satır — dört aktör yan yana.

Motor her aktör için drawItem(index) çağırır; o da sırayla:

  1. drawPendingItemBackground — düzen modunda bekleyen seçim vurgusu (çekirdek).
  2. drawItemImage — yüz resmi.
  3. drawItemStatus — isim, seviye, sınıf, göstergeler, durum ikonları.

AltMenuScreen bu iki çizim metodunu yeniden yazar:

  • Yüz: Hücrenin ortasına yakın, en fazla 144×144; savaşta olmayan üye soluk (changePaintOpacity).
  • Metin: Üstte ad + seviye; altta sınıf, placeBasicGauges (HP/MP/TP), en altta durum ikonları. Varsayılandaki “yüz solda, metin sağda tek satır” yerine dikey kart düzeni.

Çizim yardımcıları Window_StatusBase içinde tanımlıdır: drawActorFace, drawActorName, drawActorLevel, drawActorClass, placeBasicGauges, drawActorIcons.

Veri nereden gelir?

Eklenti veritabanı okumaz; yalnızca yerleşim ve çizim değişir.

  • Hangi menü komutlarının görüneceği: $dataSystem.menuCommands (editör → Sistem → Menü komutları).
  • Parti üyeleri: $gameParty.members().
  • Son seçilen komut: Window_MenuCommand._lastCommandSymbol (menüye dönünce imleç hatırlanır).

Pratik tavsiyeler

  • Küçük denemeler: Önce yalnızca maxCols / numVisibleRows değiştirin; yerleşim bozulmadan komut ızgarasını görürsünüz.
  • Çakışan eklentiler: İki eklenti aynı prototype metodunu atarsa plugins.js sırasında alttaki kazanır. Menü + seçenekler + çözünürlük birlikteyse sırayı test edin.
  • Resmi kardeş eklenti: AltSaveScreen.js kayıt ekranı düzenini benzer mantıkla değiştirir; menüyle birlikte düşünülebilir.
  • Yeni menü komutu: Window_MenuCommand.prototype.addOriginalCommands içinde this.addCommand('Etiket', 'sembol', true) ve Scene_Menu.prototype.createCommandWindow içinde setHandler('sembol', ...) (alias ile sarmalamak güvenli).
  • Tamamen özel menü: Nadiren gerekir; çoğu proje için Scene_Menu + Window_Menu* yamaları yeterlidir. Ağır UI için yeni bir Scene_* ve SceneManager.push da mümkündür.
  • Çözünürlük: Graphics.boxWidth / boxHeight o anki oyun alanıdır; UI ölçekleyen eklenti varsa (KurtsResolutionPictures) menü metinlerinde ayrı, dikdörtgenlerde genelde çekirdek koordinatları kullanılır — test ederek doğrulayın.

Özet: AltMenuScreen.js menüyü yeniden programlamaz; MZ’nin Scene_Menu + Window_MenuCommand + Window_MenuStatus üçlüsünün “nerede duracağını” ve “nasıl çizileceğini” override eder. RPGMZ’ye yabancı biri için ana fikir: sahne = pencere düzeni, pencere = liste + çizim fonksiyonları.

Kod yazımı — örnekler ve kalıplar

Aşağıdaki parçalar projedeki eklentilerden türetilmiştir; aynı düzeni TypeScript’te de kullanırsınız (sözdizimi + türler farklı olur).

1) Minimal eklenti iskeleti

Dosya yüklenir yüklenmez gövde çalışır. Üstteki yorum bloğu MZ editörü içindir; @plugindesc ve @param anahtarları Plugin Manager formunu üretir. PluginManager.parameters içindeki isim, dosya adıyla aynı olmalıdır (KurtsCameraLag.js → 'KurtsCameraLag').

//=============================================================================
// MyPlugin.js
//=============================================================================
/*:
 * @plugindesc v1.0.0 Kısa açıklama
 * @author İsim
 *
 * @param My Number
 * @type number
 * @default 10
 *
 * @help
 * Oyuncu için notlar (isteğe bağlı).
 */

(() => {
    'use strict';

    const parameters = PluginManager.parameters('MyPlugin');
    const MY_NUMBER = Number(parameters['My Number'] || 10);

    // Patch veya başka kurulum burada — aşağıdaki bölümlerde örnekler

})();

Neden IIFE? const MY_NUMBER gibi değişkenler global window’u kirletmez; isim çakışması riski azalır. Eklenti tek seferlik kurulum içindir.

2) Parametre okuma: string gelir, siz dönüştürürsünüz

parameters['X'] her zaman string veya tanımsız olabilir. Sayı ve boolean için projede şu kalıplar kullanılıyor:

// Sayı — NaN’a karşı || ile varsayılan
const lag = Number(parameters['Lag Strength'] || 0.15);

// Boolean — Plugin Manager "true" / "false" string yollar
const debug = parameters['Enable Debug'] === 'true';

// "false değilse açık" (varsayılan açık koruması)
const disable = parameters['Disable During Events'] !== 'false';

3) Prototype “alias”: önce sakla, sonra sar

MZ çekirdeğinde zaten Game_Player.prototype.initMembers var. Siz tamamen değiştirmek yerine eski fonksiyonu bir değişkende saklayıp yenisinde hem ek iş yapıp hem eskiyi çağırırsınız (KurtsPlayerDefaults ile aynı fikir).

const _Game_Player_initMembers = Game_Player.prototype.initMembers;
Game_Player.prototype.initMembers = function() {
    _Game_Player_initMembers.call(this);   // önce motorun yaptığı her şey
    this.setMoveSpeed(4);                   // sonra sizin ek ayarınız
};

Kritik: .call(this) kullanın. Böylece initMembers içindeki this yine o Game_Player örneğidir. _Game_Player_initMembers() diye parantezsiz çağırmayın — this kaybolur ve hata veya yanlış davranış olur.

4) Dönüş değeri olan patch: return zinciri

Bazı metotlar bir değer döner; önce orijinali çağırıp sonucu değiştirebilir veya koşullu olarak kendi değerinizi dönebilirsiniz.

const _Window_Base_convertEscapeCharacters = Window_Base.prototype.convertEscapeCharacters;
Window_Base.prototype.convertEscapeCharacters = function(text) {
    text = _Window_Base_convertEscapeCharacters.call(this, text);
    text = text.replace(/\[hello\]/gi, 'Merhaba');
    return text;
};

Bu, KurtsKeyMapper’daki [actionKey] değiştirmesiyle aynı yapıdır: önce çekirdek kaçışları işlensin, sonra sizin metin ekleriniz gelsin.

5) Dönüş değeri olmayan patch: yan etki + orijinal

KurtsShakePlugin gibi: önce sprite pozisyonunu motor hesaplasın, sonra sarsıntı offset’i ekleyin.

const _Sprite_Character_updatePosition = Sprite_Character.prototype.updatePosition;
Sprite_Character.prototype.updatePosition = function() {
    _Sprite_Character_updatePosition.call(this);
    const ch = this._character;
    if (!ch || ch._shakeDuration <= 0) return;
    this.x += Math.sin(ch._shakePhase) * ch._shakePower;
    ch._shakePhase += ch._shakeSpeed;
    ch._shakeDuration--;
};

(Gerçek eklentide sadece $gamePlayer filtrelenir; örnek sadeleştirildi.)

6) Çekirdeğe yeni metot ekleme (patch değil genişletme)

Orijinali saklamadan doğrudan atayabilirsiniz — dikkat: başka eklenti aynı ismi kullanırsa çakışır. Örnek: startShake.

Game_CharacterBase.prototype.startShake = function(power, speed, duration) {
    this._shakePower = power;
    this._shakeSpeed = speed;
    this._shakeDuration = duration;
    this._shakePhase = 0;
};

Olay komutundan $gamePlayer.startShake(4, 10, 20) çağrılabilir. TypeScript’te bu alanlar için tip genişletmesi (module augmentation) tanımlarsınız.

7) Harita / oyuncu yokken koruma (sık hata)

Oyun henüz yüklenmemişken veya başlık ekranındayken $gameMap null olabilir. Okumadan önce kontrol:

if (!$gameMap || !$gamePlayer) return;

KurtsMouseWheelZoom içinde $dataMap null iken displayName okunmaması gibi savunmalar vardır.

8) Global API: dışarıdan çağrılabilir fonksiyon

Başka eklentiler veya seçenek menüsü aynı kurulumu tekrarlamak için window’a fonksiyon koyabilirsiniz (KurtsKeyMapper_apply):

window.MyPlugin_reapplySettings = function() {
    // Input veya ConfigManager’ı güncelle
};

MyPlugin_reapplySettings(); // eklenti yüklenirken bir kez

9) ConfigManager ile kalıcı ayar

Kaydet/yükle nesnesine yeni alan eklemek için ConfigManager yapısına (makeData / applyData) müdahale edilir; projede KurtsOptionsMenu + KurtsFPSLogger birlikte fpsLimit, cameraLag gibi alanları başlatır. Minimum örnek — sadece varsayılan:

if (ConfigManager.myFlag === undefined) {
    ConfigManager.myFlag = true;
}

Tam kalıcılık için çekirdekteki ConfigManager.makeData / applyData alias’larına aynı anahtarı eklemeniz gerekir (OptionsMenu dosyasında uzun örnek var).

10) Üst seviye döngü: SceneManager.update

KurtsFPSLogger mantığı: önce sizin koşunuz (FPS limiti), sonra mutlaka orijinal update çağrılsın ki oyun ilerlesin.

const _SceneManager_update = SceneManager.update;
SceneManager.update = function(deltaTime) {
    // ... isteğe bağlı: bu kareyi atla / ölç ...
    _SceneManager_update.call(this, deltaTime);
};

11) İki eklenti aynı metodu sararsa

Yükleme sırası: plugins.js’te alttaki eklenti, üsttekinin sardığı fonksiyonu tekrar sarar. Zincir: Alt → Üst → Çekirdek. Uyumluluk için dokümantasyonda “şu eklentiden sonra yükleyin” denir.

12) TypeScript’e çevirirken (kısa)

  • Aynı IIFE veya derlenmiş tek modül çıktısı + MZ’nin beklediği global isimler.
  • prototype atamaları için this türü: ilgili sınıf (this: Game_Player).
  • Çekirdekte olmayan alanlar: interface Game_CharacterBase { _shakeDuration?: number } gibi augmentation.

13) Erken çıkış + çoklu koşul (örnek düşünce: animationWait)

Uzun override’larda okunabilirlik için: önce “bu eklenti bu nesneye uygulanmıyor” durumlarında orijinali çağır ve çık.

const _Game_CharacterBase_animationWait = Game_CharacterBase.prototype.animationWait;
Game_CharacterBase.prototype.animationWait = function() {
    let name = null;
    try {
        name = this.characterName ? this.characterName() : null;
    } catch (e) { /* bazı bağlamlarda yok */ }

    if (!name || !name.startsWith('$')) {
        return _Game_CharacterBase_animationWait.call(this);
    }

    // ... JSON karakterine özel hesaplama ...
    return Math.max(1, Math.round(15 / jsonPatSpd));
};

Bu yapı KurtsAnimationPlugin ile aynı fikirdir: çoğu karakterde motor davranışı bozulmaz, sadece $ sheet’lerde özel mantık çalışır.

Önerilen okuma / TypeScript’e taşıma sırası

Siz “animasyon ilk” dediniz; mantık olarak küçükten büyüğe gitmek TS öğrenimi için de iyidir:

  1. KurtsAnimationPlugin — karmaşık ama tek “oyun döngüsü” hikayesi (pattern + bekleme).
  2. KurtsKeyMapper — küçük, Input + metin kaçışı.
  3. KurtsPlayerDefaults — birkaç satır patch.
  4. KurtsFPSLogger — tek üst seviye döngü sarmalayıcısı.
  5. KurtsCameraLag — harita kaydırma.
  6. KurtsMouseWheelZoom — zoom + çözünürlük ölçeği.
  7. KurtsMapForeground — Spriteset_Map katmanı.
  8. KurtsShakePlugin — minik sprite offset.
  9. KurtsInteractionRangePlugin — tetik kontrolü + ikon sprite’ı.
  10. KurtsResolutionPictures — resim + mesaj penceresi matematiği.
  11. KurtsTranslationTooltip — mesaj penceresi + özel Window_*.
  12. KurtsOptionsMenu — en geniş: sahneler, pencereler, ConfigManager, özel sahneler.
  13. KurtsPerpectivePlugin — şu an projede kapalı; isteğe bağlı.

1. KurtsAnimationPlugin

Dosya js/plugins/KurtsAnimationPlugin.js

Amaç: img/characters/ altında $ ile başlayan sheet’ler için, aynı isimdeki JSON (LibreSprite dışa aktarımı) içindeki kare isimlerine göre animasyon kırpmak; her yön ve idle/walk/run için farklı kare sayısı; hızı f * … ifadesiyle ayarlamak; koşudan durunca kısa süre “nefes” hızı (min koşu süresi + hold + ease).

Neden sadece $ karakterler?

MZ’de $ öneki tek dosyada 3×4 grid yerine büyük sheet kullanımını ifade eder. Bu eklenti JSON tabanlı kareleri buna bağlar.

JSON kare isimlendirme

Her animasyon bir önek + indeks: ör. idleUp0, idleUp1, walkLeft2, runDown0… Eklenti bu isimleri gruplayıp frameData.animations[animKey] dizisi üretir. Eksik animasyon olursa ilk kareye düşer.

Temel motor kavramı: pattern ve animationWait

rmmz_objects.js içinde kabaca şu vardır:

  • updateAnimationCount() — hareket / adım animasyonu durumuna göre sayaç artar (koşarken 1.5 gibi).
  • animationWait() — “kaç sayaçta bir kare değişsin” eşiği (varsayılan hareket hızına bağlı).
  • updatePattern() — eşik aşılınca _pattern artar (modülü genelde maxPattern()).

Bu eklenti maxPattern() yerine JSON’daki o anki animasyon uzunluğunu kullanır; pattern() override ile dışarıya doğru indeks döner.

Hız formülü (idle / walk / run birlikte)

İfade eval ile sayıya çevrilir; f o animasyondaki kare sayısıdır. Bekleme:

wait = max(1, round(15 / jsonPatSpd))

jsonPatSpd büyüdükçe bekleme kısalır → animasyon hızlanır. İfade 0 veya geçersizse idle için 15, hareket için motorun varsayılan animationWait’i kullanılır.

getAnimationType ve _forceIdleUntilMoving

Koşu için realMoveSpeed() >= Run Speed Threshold. Duruşta justStoppedMoving ile _forceIdleUntilMoving bayrağı gelir; tekrar isMoving() olana kadar animasyon tipi idle kalır (yürüme niyeti olsa bile).

Post-run idle (durum makinesi)

  • Min run: Ardışık run kareleri sayılır; run → walk olunca sayaç sıfırlanır (kısa koşu → yürü → idle senaryosu boost almaz).
  • run → idle: Biriken kare ≥ Post Run Min Run Seconds × 60 ise (veya min 0 ise) recovery başlar.
  • Hold: Tam boost süresi.
  • Ease: Çarpan doğrusal olarak 1’e iner.

Parametre grupları

  • Hız ifadeleri: Idle/Walk/Run × dört yön.
  • Koşu eşiği, debug, hangi $ için JSON yükleneceği, statik sheet listesi.
  • Post-run: boost, min saniye, hold, ease süreleri.

Dosya js/plugins/KurtsCameraLag.js

Amaç: Harita _displayX/_displayY hedefini oyuncuya doğrusal interpolasyonla yaklaştırmak; düşük zoom’da merkez modu; oyuncu Y offset’i.

  • Game_Map.prototype.setup — harita değişince ara değişkenleri sıfırla.

TypeScript’e taşırken pratik notlar

  • Aynı davranışı koru: Önce JS’i okuyup “hangi prototype, hangi sırada” tablosunu çıkarın; TS’de birebir aynı zinciri kurun.
  • Türler: Toplulukta @types/rmmz benzeri paketler aranabilir; yoksa kritik sınıflar için kendi .d.ts minimal tanımlarınızı yazın.
  • eval: Animasyon hızı ifadeleri güvenlik ve derleme için ileride küçük bir ifade ağacına dönüştürülebilir.
  • Derleme çıktısı: Tek IIFE çıktısı üretmek genelde MZ ile uyumludur; modül sistemi kullanıyorsanız tek dosyada bundle şart.
  • Plugin meta: Üstteki /*: ... */ bloğu MZ editörü için genelde yorum olarak aynen kalır (derleyici silmemeli).
